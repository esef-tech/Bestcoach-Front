Technology Stack Risks
⚠️
Bundle Size Risk: The app ships a single bundle.js of 4,694 KiB with no code-splitting. All routes are loaded eagerly, causing a 2,280 ms Total Blocking Time. CRA (Create React App) does not support automatic route-level code splitting without manual lazy() configuration.

All modal components (Login, Signup, MFA) are mounted unconditionally on initial render. React's User Timing marks show 387 mount measures at load time. Use lazy rendering with React.lazy() and Suspense, and only mount modals when triggered.
// BEFORE: All modals mounted unconditionally
return (
  <div>
    <LoginModal />
    <SignupModal />
    <MFAVerificationModal />
    ...
  </div>
);

// AFTER: Lazy-mount on user trigger
const LoginModal = React.lazy(() => import('./LoginModal'));

return (
  <div>

Interface Test Issues
BUG

Non-composited animation on handwritten-text element

The span.handwritten-text element uses a CSS animation that modifies the width property. Width changes are not GPU-compositable and force layout recalculation on every frame, causing jank. Fix: animate transform: scaleX() or opacity instead of width.

/* BEFORE — triggers layout recalculation */
.handwritten-text { animation: reveal 1s ease; }
@keyframes reveal { from { width: 0; } to { width: 100%; } }

/* AFTER — GPU composited, no layout recalculation */
.handwritten-text {
  clip-path: inset(0 100% 0 0);
  animation: reveal 1s ease forwards;
}
@keyframes reveal {
  to { clip-path: inset(0 0% 0 0); }
}

Phase 5D — Compatibility Testing

Cross-browser, cross-device, and cross-OS validation.

Phase 05-D
Issues Identified
Warning

Legacy JavaScript transpilation (core-js@3.48.0)

The bundle includes core-js-pure@3.48.0 polyfills. Lighthouse flags that many of these polyfills are unnecessary for modern browsers (Baseline features). This adds unnecessary code to the bundle.

  • Update .browserslistrc to target only modern browsers: >0.5%, last 2 Chrome versions, last 2 Firefox versions, last 2 Safari versions, not IE 11
  • Configure @babel/preset-env with useBuiltIns: 'usage' and target modern browsers to tree-shake unused polyfills.
Warning

Back/Forward Cache (bfcache) incompatibility

Pages with an active WebSocket connection cannot enter the back/forward cache. This means every back-navigation forces a full page reload (including the 7 s LCP delay again). This is a pending browser support issue; the WebSocket connection should be closed before the page enters the bfcache state.

// Add pagehide/pageshow listeners to handle bfcache
window.addEventListener('pagehide', (e) => {
  if (e.persisted) {
    // Page entering bfcache — close WebSocket
    socket.close();
  }
});
window.addEventListener('pageshow', (e) => {
  if (e.persisted) {
    // Page restored from bfcache — reconnect WebSocket
    reconnectSocket();
  }
});
Warning

React non-boolean attribute prop warning (Console error)

Console error in bundle.js:8044: Received true for a non-boolean attribute smooth. A component is passing smooth={true} to a DOM element where smooth is not a valid HTML attribute. This causes hydration warnings and pollutes the console.

// Find the component passing smooth prop to a DOM element

// Fix: use string "true" or filter prop before forwarding to DOM
const ScrollLink = ({ smooth, ...rest }) => (
  <a {...rest} data-smooth={smooth ? "true" : "false"} />

Vulnerability Assessment
VULN-01

XSS Risk — No Content-Security-Policy

Critical

Risk: Without a CSP, any injected script (via user input, third-party widget, or CDN compromise) will execute in the user's browser. The app loads 6 different third-party domains (GTM, Google Fonts, Netlify, Firebase, Squarespace CDN, community domains).

Fix for Vercel — add to vercel.json:

{
  "headers": [{
    "source": "/(.*)",
    "headers": [
      {
        "key": "Content-Security-Policy",
        "value": "default-src 'self'; script-src 'self' https://www.googletagmanager.com https://www.google-analytics.com https://app.relevanceai.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https://bestcoachmusic.netlify.app https://images.squarespace-cdn.com https://www.communitymusicschool.com https://www.washingtonperformingarts.org; connect-src 'self' https://firebase.googleapis.com; frame-ancestors 'none'"
      },
      { "key": "Strict-Transport-Security", "value": "max-age=31536000; includeSubDomains" },
      { "key": "X-Frame-Options", "value": "DENY" },
      { "key": "X-Content-Type-Options", "value": "nosniff" },
      { "key": "Cross-Origin-Opener-Policy", "value": "same-origin" },
      { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" }
    ]
  }]
}
VULN-02

Information Disclosure — Firebase Config Exposed

Medium

The Firebase configuration endpoint (firebase.googleapis.com/…/webConfig) is visible in the network requests. Firebase API keys in React apps are client-facing by design, but access must be restricted using Firebase Security Rules and App Check to prevent unauthorised API usage.

  • Enable Firebase App Check (reCAPTCHA Enterprise) to prevent API abuse from unauthorised origins.
  • Restrict Firebase API key in Google Cloud Console to only the Vercel production domain.
  • Ensure Firestore Security Rules do not allow unauthenticated reads/writes to sensitive collections.
VULN-03

Unused Preconnect — app.relevanceai.com

Low

A <link rel="preconnect" href="https://app.relevanceai.com/"> is declared in the document but the origin is never actually requested during page load. Unused preconnects waste a TCP handshake, consume browser connection pool slots, and disclose external service dependencies.

  • Remove the unused preconnect hint from public/index.html if Relevance AI is not actively used on page load.
  • Only retain preconnects for origins that are requested in the first 2 seconds of load.
VULN-04

Duplicate Google Analytics Tags

Low

Two GA4 measurement IDs (G-1PCHN98LJ5 and G-1PCHN98LJS) are both firing via GTM. The second appears to be a mistyped version of the first (J vs 5). This inflates analytics event counts and adds ~240 ms of unnecessary main-thread JavaScript execution.

  • Log into GTM container, identify and remove the duplicate GA4 Configuration tag.
  • Verify the correct Measurement ID is used in all GA4 event tags.

Fix 1 — Code-Split the Bundle (Savings: ~3,970 KiB unused JS)
Impact: Critical

bundle.js is 4,694 KiB — largest single-file blocker (TBT & FCP)

Est. +30–40 pts Performance

The entire React application is shipped in a single bundle. 3,740 KiB of that is unused JavaScript on the initial page load. Implement React route-based code splitting using React.lazy().

// src/App.js — route-level lazy loading
import React, { lazy, Suspense } from 'react';
import { BrowserRouter, Routes, Route } from 'react-router-dom';

const Home      = lazy(() => import('./pages/Home'));
const Community = lazy(() => import('./pages/Community'));
const Events    = lazy(() => import('./pages/Events'));
const Company   = lazy(() => import('./pages/Company'));
const Blog      = lazy(() => import('./pages/Blog'));

function App() {
  return (
    <BrowserRouter>
      <Suspense fallback={<PageLoader />}>
        <Routes>
          <Route path="/"           element={<Home />} />
          <Route path="/community"  element={<Community />} />
          <Route path="/events"     element={<Events />} />
          <Route path="/company"    element={<Company />} />
          <Route path="/blog"       element={<Blog />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}
Fix 2 — Eliminate Render-Blocking Google Fonts (Savings: 720 ms)
Impact: High

Google Fonts CSS blocks rendering for 740 ms

Est. +8–12 pts Performance

The Dancing Script font CSS is loaded via a synchronous <link rel="stylesheet"> tag, blocking the initial render for 740 ms. Fix using font-display: swap and load asynchronously.

<!-- public/index.html — BEFORE (render-blocking) -->
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Dancing+Script:wght@600&display=swap">

<!-- AFTER — preconnect + async load -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="preload" as="style"
  href="https://fonts.googleapis.com/css2?family=Dancing+Script:wght@600&display=swap"
  onload="this.onload=null;this.rel='stylesheet'">
<noscript>
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Dancing+Script:wght@600&display=swap">
</noscript>
Fix 3 — Optimise LCP Image (Savings: 372 KiB, LCP -4,280 ms)
Impact: Critical

Carousel LCP image (TSS_NEW.webp) has 4,280 ms resource load delay

Est. +15–20 pts Performance

The LCP image is discovered in the HTML but has a 4,280 ms resource load delay due to the bundle.js loading first. The image is also oversized (1290×1600 served at 226×280). Fix with fetchpriority="high", responsive sizes, and correct dimensions.

{/* In the carousel JSX — BEFORE */}
<img src={carouselImg} className="d-block w-100 carousel-image" />

{/* AFTER — fetchpriority, explicit dimensions, srcset */}
<img
  src={carouselImg}
  srcSet=`${carouselImg226} 226w, ${carouselImg452} 452w`
  sizes="(max-width: 576px) 226px, 452px"
  width={226}
  height={280}
  fetchPriority="high"
  loading="eager"
  decoding="async"
  className="d-block w-100 carousel-image"
  alt="Talented Students Showcase — Bestcoach Music"
/>

Additionally, resize the source image server-side: a 226×280 display target only needs a 452×560 source (2× for retina). Compress to <30 KiB using sharp or Squoosh.

        "value": "public, max-age=86400, stale-while-revalidate=604800"
      }]
    },
    {
      "source": "/(.*).html",
      "headers": [{
        "key": "Cache-Control",
        "value": "no-cache"
      }]
    }
  ]
}

CRA-built JS/CSS filenames include a content hash (e.g., bundle.3a6f9e.js), making them safe for 1-year immutable caching. The HTML file should never be cached.
